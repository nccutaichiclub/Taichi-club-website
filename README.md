## 網站架構總覽

網站目前有 **5 個頁面**，彼此透過同一份導覽列互相連結：

| 頁面 | 網址 | 對應的資料檔 |
|---|---|---|
| 首頁主殿 | `index.html` | `data/home.json` |
| 法門深造 | `gongfa.html` | `data/gongfa.json` |
| 活動介紹 | `activities.html` | `data/activities.json` |
| 修煉日程 | `calendar.html` | `data/calendar.json` |
| 常見問題 | `faq.html` | `data/faq.json` |

**運作邏輯**：每個網頁本身只是「空殼」，實際顯示的文字、圖片，是網頁打開時用 JavaScript 去讀取對應的 `data/*.json` 檔案，再動態把內容「填」進網頁裡。也就是說：

> **改內容，不用碰 HTML 檔，只要在後台改對應的 JSON 資料就好。**

只有「想改版面配置、改樣式、加新功能」的時候，才需要動到 `.html`／`.js`／`.css` 這些程式碼檔案。

## 各檔案功用詳解

### 網頁本體（5 個 `.html` 檔）

每個頁面的程式碼結構都長得差不多：

1. `<head>` 裡引入字體、Tailwind CSS（版面框架）、`css/base.css`
2. `<body>` 一開始先引入 `js/lang.js` 跟 `js/header.js`，讓導覽列自動產生
3. 頁面主要內容區塊，一開始通常是「載入中...」的預留文字
4. 最下面一段 `<script>`，負責 `fetch()` 抓對應的 `data/*.json`，抓到之後把資料「塞」進畫面上的各個欄位

**index.html（首頁）比較特別**：它沒有引入 `css/base.css` 跟 `js/tailwind-config-sub.js`，因為首頁完整啟用了 Tailwind 的預設樣式重置（其他四頁為了保留原本手寫的樣式而關閉了這個功能，細節見下方「技術注意事項」）。

### `js/lang.js`（共用邏輯核心）

這支檔案負責兩大類功能：

**① 中英文切換**
- `getLang()` / `setLang()`：讀取／寫入瀏覽器儲存的語言偏好（用 `localStorage`，切頁面會記住）
- `pickText(obj, fieldName)`：依目前語言，從資料裡挑出對應欄位（例如 `title` 或 `title_en`）
- `applyLangToData(data)`：**整批**把抓回來的 JSON 資料轉換成目前語言——凡是欄位名稱後面有 `_en` 版本、且目前是英文模式、且 `_en` 有填內容，就直接覆蓋過去。轉換完之後，後面所有渲染程式碼完全不用管語言問題，抓到什麼就是該顯示的語言
- `initLangSwitcher(buttonId)`：綁定「EN／中文」按鈕的點擊事件

**② 共用小工具函式**（原本五個頁面各自重複寫一份，現在統一放這裡）
- `resolveImagePath(path)`：修正圖片路徑，避免開頭多一個 `/` 導致抓不到圖
- `setText(id, value)` / `setTextAll(className, value)`：把純文字塞進畫面上的元素
- `setHtml(id, value)`：把「支援標記語法」的文字塞進畫面（見下方標記語法說明）
- `paragraphize(text)`：把後台打的一大段文字，依空白行自動分段
- `parseInlineMarkup(text)`：**標記語法解析器**。後台文字裡如果有 `**文字**` 會變成**粗體**；`` `文字` `` 或 `[[文字]]` 會變成<span style="color:#B89742">金色標註文字</span>

### `js/header.js`（共用導覽列）

五個頁面的導覽列（品牌牌匾、選單連結、手機漢堡選單、中英文切換鈕）全部由這支檔案統一產生。網頁裡只留一個空的 `<div id="site-header"></div>` 插槽，`header.js` 會：

1. 依網址自動判斷「現在是哪一頁」，把對應的選單項目標記成使用中樣式
2. 把整段導覽列 HTML 塞進插槽
3. 綁定手機漢堡選單開關、初始化語言切換鈕
4. 抓 `data/home.json` 的 `nav` 欄位填入導覽文字

> **之後要新增頁面（例如「相簿集錦」）**，只要在 `header.js` 最上面的 `PAGE_MAP` 和 `NAV_ITEMS` 各加一行，五頁的選單就會自動一起更新，不用逐頁修改。

### `js/tailwind-config-sub.js`

四個子頁（法門深造／活動介紹／修煉日程／常見問題）共用的 Tailwind 顏色與字體設定檔（政大太極社的金色/墨色/松柏綠配色）。首頁不使用這份設定，自己有獨立的版本寫在 `index.html` 裡面。

### `css/base.css`

四個子頁共用的基礎樣式：容器寬度、標題樣式、圖片自動縮放保護、金色標註樣式等。各頁如果有自己的微調（例如 `calendar.html` 的松柏綠比較深），會寫在該頁自己的 `<style>` 裡覆蓋這份基礎設定。

### `data/*.json`

後台實際編輯的內容，全部是 JSON 格式。**不建議手動編輯這些檔案**，請透過後台系統操作（見下一節），避免打錯字破壞 JSON 格式導致整頁讀取失敗。

### `admin/index.html` 與 `admin/config.yml`

`admin/index.html` 只有一行，負責載入 Sveltia CMS 這套後台系統。真正決定「後台長什麼樣子、有哪些欄位可以填」的是 `admin/config.yml`——如果之後想在後台新增欄位，就是改這個檔案（YAML 格式，改動時建議請比較熟悉的人操作，或是拿去請 AI 工具協助）。

## 後台系統操作說明

### 登入後台

1. 前往 `https://nccutaichiclub.github.io/Taichi-club-website/admin/`
2. 用有這個 repo 編輯權限的 GitHub 帳號登入、授權
3. 登入後左側會看到幾個分類（依 `config.yml` 目前設定）：
   - 🏠 首頁主殿管理
   - 🥋 法門深造頁管理
   - 🎉 活動介紹頁管理
   - 📅 修煉行事曆管理
   - ❓ 常見問題頁管理

### 編輯內容的基本流程

1. 點選左側分類 → 進入該頁的編輯畫面
2. 修改想改的欄位
3. 存檔（Sveltia CMS 會直接把改動送回 GitHub repo）
4. GitHub Pages 通常會在 **1 分鐘內**自動重新部署，重新整理網頁就能看到更新（如果沒看到，等一下或是強制重新整理 `Ctrl+F5`）

### 常見欄位類型

| 欄位類型 | 說明 |
|---|---|
| 一般文字欄位 | 單行輸入框，通常有字數建議（超過會影響版面，請盡量遵守） |
| 長文字欄位 | 多行輸入框，可以打好幾句話 |
| **Markdown 欄位（有工具列）** | 上方有 **Bold（粗體）** 跟 **Code（金色標註）** 兩顆按鈕，選取文字後點擊即可套用，見下方說明 |
| 圖片欄位 | 點擊上傳圖片，會自動存到 `assets/uploads/` |
| 清單（列表）欄位 | 可以「新增」「刪除」多筆資料，**可以直接拖曳調整順序** |
| 下拉選單 | 固定選項，例如月份分類 |

### 文字標記語法（粗體 / 金色標註）

部分長文字欄位（例如常見問題的答案、活動介紹、法門說明等）上方會有工具列：

- 選取一段文字，點 **Bold** → 自動變成 `**文字**` → 網頁上會顯示**粗體**
- 選取一段文字，點 **Code**（反引號圖示）→ 自動變成 `` `文字` `` → 網頁上會顯示**金色標註**（這是借用 Code 按鈕做的效果，不是真的程式碼格式，不用擔心）

也可以手動直接打這些符號（例如打 `[[重要]]` 一樣會變金色），不一定要靠按鈕。

### 中英文雙語欄位

大部分文字欄位下面都會有一個「(English)」版本的欄位（例如 `標題` 底下會有 `標題 (English)`）：

- **英文欄位都是選填**，沒填的話網頁的英文模式會自動 fallback 顯示中文版，不會開天窗
- 想要有雙語顯示，就把對應的英文欄位也填上翻譯即可
- 訪客可以透過網頁右上角（電腦版）或牌匾旁邊（手機版）的「EN／中文」按鈕切換語言

### 圖片與檔案上傳

- 點擊圖片欄位會跳出上傳視窗，選好圖片後系統會自動存到 `assets/uploads/` 資料夾，不用自己管理檔名或路徑
- 建議上傳前先把圖片壓縮到合理大小（例如網頁用途 1600px 寬已經很足夠），避免網站載入太慢

## 常見維護情境

**Q：想換學期，行事曆要怎麼更新？**
A：到「📅 修煉行事曆管理」，改「目前學期標題」欄位（例如 115-1 → 115-2），然後把「行事曆活動列表」裡的分類（例行活動／上半學期／下半學期）跟每筆活動內容依新學期調整。

**Q：想加一個新的常見問題？**
A：到「❓ 常見問題頁管理」，選一個既有分類（或新增分類），在底下的「問題」清單點「新增」，填問題跟答案即可。分類本身也可以拖曳排序，底下問題會整組跟著移動。

**Q：想換首頁的輪播照片？**
A：到「🏠 首頁主殿管理」→「Hero 主視覺區」，電腦版跟手機版的輪播圖片是分開上傳的欄位（手機版建議直式照片，電腦版建議橫式）。

**Q：想加一個新頁面（例如「相簿集錦」）？**
A：這個需要動到程式碼，建議請熟悉的人或 AI 工具協助，大致流程是：
1. 複製一個現有子頁（例如 `faq.html`）當範本，改標題跟內容區塊
2. 在 `js/header.js` 的 `PAGE_MAP` 跟 `NAV_ITEMS` 加入新頁面
3. 在 `data/` 資料夾新增對應的 JSON 檔案
4. 在 `admin/config.yml` 新增對應的後台編輯欄位

**Q：換幹部了，後台的 GitHub 帳號權限要怎麼交接？**
A：去 GitHub repo 的 `Settings → Collaborators`，把新幹部的 GitHub 帳號加進去給 Write 權限，之後他就能直接用自己的帳號登入後台。不建議共用同一組帳號密碼。

## 技術注意事項

以下是給比較熟悉網頁開發、或未來要動到程式碼的人看的重點提醒：

1. **`index.html` 必須留在根目錄**：GitHub Pages 預設會抓根目錄的 `index.html` 當首頁，其他四個頁面也建議留在根目錄，因為外部已經有分享出去的網址連結（例如 IG 簡介），搬動路徑會讓那些連結失效。

2. **四個子頁關閉了 Tailwind 的 `preflight`**：這是為了保留原本手寫的 CSS 樣式不被 Tailwind 的預設重置覆蓋。但這連帶少了幾個瀏覽器預設會有的保護，已經手動補回來，包括：
   - `box-sizing: border-box`（沒有這條，任何有 `padding` 的區塊實際寬度都會比容器多撐出 padding 的量，這是手機版內容跑版、溢出畫面的常見根因）
   - `img { max-width: 100%; height: auto; }`（圖片自動縮放保護）
   - 表單元件（按鈕）預設不會繼承頁面字體，也已手動用 `font-family: inherit` 補上

3. **`overflow-x: hidden` 要同時設在 `html` 和 `body`**：只設 `body` 對 `position: fixed` 的元素（例如導覽列）不一定有效，因為 fixed 元素是以整個瀏覽器視窗為基準定位，不受 `body` 的 overflow 裁切影響。

4. **`data/*.json` 抓取路徑是相對於「網頁本身的網址」，不是相對於 JS 檔案的位置**：所以就算把 `lang.js`／`header.js` 搬到 `js/` 資料夾，裡面 `fetch('data/home.json')` 這種相對路徑完全不受影響，因為瀏覽器是以「目前開啟的網頁在哪裡」去解析路徑的。

5. **Sveltia CMS 目前不支援自訂欄位工具（`registerFieldType`）**：如果之後想要更多客製化的編輯器按鈕，目前只能借用內建 `markdown` 欄位的 `buttons` 選項做有限度的客製化（就是本站金色標註按鈕的做法），無法做到完全自訂。官方文件顯示這個功能「即將推出」，可以持續關注。
